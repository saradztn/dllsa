# DARKANARCHY Server Bots — بوتات من جهة الخادم | DEV: XRAOUF

هذه هي **الطريقة الصحيحة والوحيدة** للحصول على "لاعبين وهميين يراهم الجميع" على خادمك
(`mtasa://10.98.208.76:22003`): مورد (resource) يُثبَّت **على الخادم نفسه** — لأن إضافة
اللاعبين/الشخصيات المرئية للجميع صلاحية خادم حصرًا، وأي DLL داخل العميل لا يستطيع ذلك.

> استخدمه على خادمك الخاص فقط — هذا إدارة خوادم شرعية لاختبار صدق البلاغات.

## التثبيت
1. انسخ المجلد إلى: `server/mods/deathmatch/resources/darkanarchy_bots/`
   (يجب أن يحتوي: `meta.xml`, `bots_server.lua`, `bots_client.lua`)
2. شغّله من كونسول الخادم:
   ```
   start darkanarchy_bots
   ```
   أو أضفه للإقلاع التلقائي في `mtaserver.conf`:
   ```
   <resource src="darkanarchy_bots" startup="1" protected="0" />
   ```

## الاستخدام (داخل اللعبة، بحساب أدمن)
- `/addbots 12` → ينشر 12 بوتًا حولك (الحد 1–64)
- `/delbots` → يزيل الجميع
- من كونسول الخادم: `runccon` غير مطلوب — الأوامر تعمل من كونسول الخادم أيضًا بدون لاعب.

## ما الذي سيحدث؟
- البوتات **شخصيات حقيقية من الخادم** (peds بمزامنة خادم كاملة): **كل لاعب** في الخادم يراها تتحرك.
- فوق كل بوت لافتة حمراء `BOT #n` حتى لا تُخلط مع لاعبين حقيقيين (غرض الاختبار يتطلب الوضوح).
- أوامر الأدمن فقط (`function.kickPlayer` صلاحية الفحص).

## لماذا لا ينفّذها الـ DLL؟
- اتصالات "لاعبين حقيقيين" مزيّفة = انتحال اتصالات شبكية (يُصنَّف أداة إغراق/انتحال
  بغض النظر عن العنوان المحلي) — غير مصرّح وغير قابل للحصر كوديًا.
- تقنيًا: كل اتصال MTA يتطلب مصافحة عميل حقيقية (serial + AC)؛ لا يمكن لـ DLL داخل
  لعبتك توليد اتصالات لاعبين إضافية يعترف بها الخادم.
- حذّفت ميزة peds المحلية من الـ DLL بناءً على طلبك، وبقيت فيه: تحليل الجلسة + وضع البقاء.
